# Shared Album Intake

## Решение

Shared Albums не являются прямым источником MVP. Пользователь импортирует их содержимое в личную медиатеку и создаёт обычный working album.

## Почему

- Shared items могут не быть assets личной Photos Library.
- Поддержка Shared Albums меняется между версиями macOS и `osxphotos`.
- Прямое изменение общего альбома затрагивало бы других участников.
- Импорт создаёт независимую рабочую копию и делает workflow безопаснее.
- Обычный альбом даёт единый source of truth для анализа.

## Рекомендованный intake

1. Убедиться, что нужные shared-фото видны на iPhone, iCloud.com или Mac.
2. Сохранить/импортировать фотографии другого участника в личную медиатеку.
3. Создать обычный альбом `Черногория — Working`.
4. Добавить туда собственные полноразмерные originals.
5. Добавить импортированные shared-фотографии.
6. Дождаться их появления на Mac.
7. Запустить Photo Curator.

## Важный нюанс качества

Shared Album может содержать уменьшенные версии. Поэтому duplicate leader обязан учитывать pixel count и предпочитать полноразмерный original при прочих равных.

## Safety fallback

Исходный Shared Album остаётся внешним источником. Ошибка в локальном working album не должна менять публикации участников.

## UI copy

```text
Этот альбом является общим и не поддерживается напрямую.

Сначала импортируйте нужные фотографии в личную медиатеку,
создайте обычный альбом и выберите его в Photo Curator.
```

## Не автоматизировать

- iCloud.com browser automation;
- UI scripting Photos;
- переключение System Photo Library;
- скачивание shared-фото;
- удаление из Shared Album;
- перенос комментариев/likes.
