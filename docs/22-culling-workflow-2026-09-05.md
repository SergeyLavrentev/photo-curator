# Упрощение до «Оставить / К удалению»

По уточнению пользователя основной результат — список неудачных и избыточных фотографий,
которые можно проверить и удалить. Best, Alternative, Review и размер будущей подборки
убраны из основного UI. Рейтинг и legacy publish API сохранены для совместимости старых
данных и проверок, но больше не определяют пользовательские категории.

Decision model v8 сохраняет отдельные `auto_culling` и причину. «К удалению» содержит
подтверждённые повторы серии и кандидатов с конкретными техническими признаками. Низкий
aesthetic score не превращает уникальный кадр в брак. Представитель серии, отличающиеся
моменты, избранное, правки, неоднозначные группы и недоступный анализ защищены. Пользователь
может изменить категорию и отменить своё решение; ручное решение имеет приоритет.

Удаление реализовано отдельным native PhotoKit путём: список изображений и имён, явная
отметка проверки, кнопка «Удалить N фото из медиатеки», backend confirmation, проверенный
SQLite backup, повторная проверка membership/source revision/permissions и однократный
`PHAssetChangeRequest.deleteAssets`. Список действует 15 минут; повтор начатого запроса
запрещён. Текст предупреждает об удалении из всей медиатеки, её альбомов и iCloud-устройств.
После результата перечитываются UUID; в каталоге скрываются только фактически отсутствующие
assets. Изображения для проверки, история и learning corpus сохраняются.

Локальные/Shared-копии не разрешают угадывать оригиналы для удаления. Для этого пути требуется
новый анализ поддерживаемого обычного альбома PhotoKit с source revision. Общие альбомы,
которыми PhotoKit не позволяет управлять как обычной медиатекой, остаются для ручной работы
в Photos. Неизвестный исход после остановки процесса требует проверки Photos и обновления
анализа; автоматического retry нет.

Текущая проверка не удаляет пользовательские фотографии, не меняет установленное приложение,
не делает commit/push и не является real PhotoKit deletion acceptance.

API: [Apple PHAssetChangeRequest](https://developer.apple.com/documentation/photos/phassetchangerequest).

## Проверка сборки и результата

`make lint`, 297 tests, `make app` и `make verify-app` прошли. Запущена сборка
0.2.0 (1) из `build/macos/PhotoCurator.app`, SHA-256 исполняемого файла
`3d34051e464fe5926c68ef9902472a241333a68f1050239d8e209c164ab17fe9`.
Установленная `/Applications/PhotoCurator.app` не заменялась.

В локальном прогоне «Синий жук и бобр» — 1734 фото: 439 предложений к удалению,
1295 оставить. Из 439: 356 дополнительных повторов, 72 по прежним правилам
подтверждённых дубликатов/дефектов, 10 по признакам размытия и 1 по экспозиции.
Это предложения для проверки, а не подтверждение, что все 439 нужно удалить.

В реальном UI проверены две категории, ручное сохранение кадра (438/1296), отмена
(возврат 439/1295), отказ удаления оригиналов через локальную копию. Сам лист
подтверждения проверен в отдельном preview без проекта и worker: список и предупреждение
читаются, кнопка недоступна до отметки проверки. PhotoKit deletion не вызывался.
SQLite integrity — `ok`, schema 30, исходные 80 индивидуальных labels сохранены.

Сопоставление с ранее независимо оценёнными 48 фотографиями: из 16 визуально сильных
12 остаются, 4 предложены как повторы; из 16 слабых 4 предложены, 12 остаются.
Это не precision/recall: исходная оценка красоты не размечала избыточность серии.
Повторно просмотрены пары IMG_5922/5923 и IMG_5857/5858: сцены практически одинаковые,
оставить один кадр разумно, хотя оба кадра сами по себе пригодны. Пропуск кадров со
слабой композицией остаётся ограничением движка. Утверждать доказанное улучшение
эстетического отбора или готовность удаления без пользовательской проверки нельзя.
Оценки ассистента не добавлялись в пользовательский обучающий корпус.

Локальное evidence: `build/evidence/culling-2026-09-05/runtime-result.json` и
`visual-culling-comparison.json`; исходный подробный аудит — `docs/21-review-2026-09-05.md`.


## Прямое удаление выбранных фотографий

Последующая доработка: «Удалить из медиатеки…» в контекстном меню одного фото и
кнопка удаления выбранных доступны в обеих категориях. Явный выбор не требует
предварительно менять решение движка; Favorite/edited отображаются в подтверждении.
Отмена сохраняет прежнее решение. Массовый запрос без UUID по-прежнему ограничен
категорией «К удалению». Перед показом списка запрашивается разрешение Photos, если
пользователь ещё не отвечал на системный запрос. Реальное удаление выполняет тот же
PhotoKit change request после подтверждения. Вызов не подменён dry run.

299 тестов, lint, app/DMG build и verify-app прошли. В запущенном приложении проверены
кнопка в «Оставить» и отказ для локальной копии. Удаление реальных пользовательских
assets не выполнялось; установленная версия не заменялась. SHA-256 новой сборки: `24a3ba8274c4ef3a4cb5b2514158bce4b21e22725d31a6cd01f88908469072af`.
Evidence: `build/evidence/culling-2026-09-05/direct-deletion-result.json`.
