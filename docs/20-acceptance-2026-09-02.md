# Acceptance evidence — 2026-09-02 durable Quality Lab learning

This document records implementation, automated-test and package-build evidence for persistent
local learning. It is not human acceptance of selection quality, a real installed-app run or a
release claim.

## Implemented boundary

- SQLite schema v27 introduced `learning_contexts`, `learning_rounds`, `learning_assets`,
  `learning_preferences`, `learning_series`, project working bindings and migration audit.
  Schema v28 additionally preserves human notes.
- Durable tables have no foreign key to `projects`, `assets`, album snapshots or preview files.
  They retain copied feature vectors, source revision hashes, feature/model provenance and
  pseudonymized album-wide episode contexts.
- Every context is locked to `training` or `held_out`. A conflicting import or new round fails
  closed. Held-out rows are not copied into `preference_examples` and never participate in fit.
- Training preferences, ordered Top-K relations and explicit series-leader relations update
  `pairwise-linear-v5-durable-quality-corpus`. The ranker consumes Apple Vision/Core ML feature
  snapshots; no foundation or Core ML model is retrained.
- Quality disposition and defect truth is retained for evaluation but does not change automatic
  delete/reject safety. PhotoKit and source-library boundaries are unchanged.
- Native worker startup attempts an idempotent migration of existing Quality Lab rows. Legacy
  project-scoped evidence is conservatively locked to held-out. Incomplete feature/source/model
  provenance creates a failed audit row and project deletion remains blocked.
- Project deletion migrates current evidence before the existing verified-backup/cascade path;
  the durable corpus and trained ranker survive. Restarting labelling creates a new attempt and
  keeps the prior attempt as `superseded`.
- Full corpus/ranker deletion is a separate `confirmed=true` action with a verified SQLite backup
  and `destructive-actions.jsonl` request/completion entries. It does not delete a project or
  touch Apple Photos.
- Corpus export/import preserves split locks, human-origin flags, feature/model provenance and
  copied vectors. Import rejects prediction-origin payloads, schema drift, corrupt vectors and
  train/held-out context overlap.
- SwiftUI separately presents accumulated training, the active attempt and frozen evaluation,
  including train/held-out context counts and active ranker version.

## Migration compatibility

- v26 databases migrate transactionally through v27/v28 under the existing pre-migration online
  backup and post-schema verifier.
- Existing Quality Lab rows are not rewritten as product decisions and their project working
  projection remains compatible with the acceptance exporter.
- Existing global Personal Taste examples remain available. A previous ranker version is retrained
  to v5 only when compatible calibration examples are sufficient; otherwise it remains honestly
  collecting/stale rather than accepting incompatible features.
- Migration is repeatable for an unchanged input fingerprint and does not duplicate durable rows.
